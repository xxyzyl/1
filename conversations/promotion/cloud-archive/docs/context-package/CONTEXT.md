# CONTEXT.md

## 设计来源与版本

本工程包根据截至 2026-09-07 的项目讨论整理。项目正式名称为“人生管理系统 4.0”。此前设计还包括“决策引擎 3.0”，其 S1—S8 流程、状态记录规则和协作契约是 4.0 的核心基础。

## 已形成的设计资产

- 4.0 总体设计：总控、9 个领域、23 个共享能力模块、资源协调和反馈闭环。
- 决策流程图、总体设计图、子智能体协作图和详细 PPT。
- 系统控制论/系统工程启发：观测指标不等于真实状态；反馈存在延迟；调整力度和频率可能导致失稳；局部优化必须接受整体约束检查。
- 资源核算规则：共享任务去重、共同资源只计一次、时间/资金/精力/承诺分开管理。
- 主动服务协议：授权读取数据，主动发现缺口，主动补问，证据足够后建议，冲突时交用户确认。

## 重要产品判断

这是“持续协调平台”，不是自动人生评分器，也不是替用户承担价值选择的机器人。用户决定什么值得追求；系统负责整理事实、协调资源、暴露取舍、跟踪结果和根据反馈更新。

早期产品只需要目标、可用时间和现有承诺即可运行。优先验证一种日历或任务接入；没有平台接口时，提供文件导入或手动确认。敏感数据遵循最小必要原则。

## 不应误读的边界

PPT、图表、方法论、示例测试和已有 Skill 不等于已经有可运行软件。当前还没有可宣称的生产后端、真实平台连接、后台定时服务、通知系统、长期效果、商业收益或成功率。

## 推荐第一条开发路径

先做脱离外部平台的本地 MVP：输入“职业转型”问题 → 收集目标/时间/承诺/底线 → 生成有限快照 → 运行 S1—S8 → 展示方案与复核 → 保存用户选择 → 创建试行行动 → 手动录入结果 → 回到反馈阶段。这个闭环通过后再接入日历或任务平台。
