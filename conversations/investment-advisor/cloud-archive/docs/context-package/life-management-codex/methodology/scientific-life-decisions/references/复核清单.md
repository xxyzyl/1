# 决策复核清单

版本：3.0。以具体证据或产物标明“已检查／未检查／不适用及原因”，不能只勾选或宣称“科学”。

| 检查项 | 具体问题 | 可检查产物 |
| --- | --- | --- |
| 目标与价值 | 是否来自用户，是否遗漏重要取舍？ | 用户表述、目标与约束 |
| 方法 | 为什么使用该方法，条件是否满足？ | 方法编号、输入、应用结果和局限 |
| 证据 | 是否实际查阅、可定位、适时和适用？ | 来源、日期、E 编号与主张对应 |
| 反向材料 | 是否寻找反对理由并处理冲突？ | 替代解释、最强反对理由和未决冲突 |
| 方案 | 是否有现实备选，硬约束是否优先？ | 方案对比与排除理由 |
| 数字 | 来源、单位、口径与计算是否可复现？ | 输入、公式、运行结果或未计算说明 |
| 因果 | 是否把相关当因果？ | 识别假设、替代解释与局限 |
| 不确定性 | 什么变化会改变建议？ | 情景、敏感性和反转条件 |
| 现实后果 | 可逆性、不可承受损失与他人权益是否检查？ | 后果分析和需要的外部核实 |
| 行动 | 能否开始、检查、停止？ | 资源边界、验收与退出条件 |
| 反馈 | 能否回看当时的判断？ | 原始记录和复盘日期或触发条件 |
| 建议状态 | 是否与证据缺口匹配？ | 三种建议状态、具体缺口 |
| 输入版本 | 比较与复核是否仍适用于当前输入？ | 版本、指纹、受影响项 |
| 用户与执行状态 | 是否把建议、选择和实际行动混淆？ | 用户选择来源、授权范围、真实行动记录 |

注明谁核查了什么、材料或计算是什么、哪些未查。模型自审不能写成“独立专家验证”。用户可以抽查一个来源、重算一个关键数字、询问反对理由或改变一个关键条件，检查建议是否随之合理变化。

## 结构检查工具

使用 Skill 目录内的 `scripts/check_decision.py` 检查实际决策文件的绝对路径；3.0记录同时传入 `--state 状态记录.json`。脚本检查基本字段、必需章节、方法编号及少量明显状态冲突。它不联网，不验证事实、方法适用性、计算结果、专业正确性和现实后果。

格式完整的虚假内容也可能通过。脚本不是已安装的客户端自动拦截器；本 Skill 要求调用，是否真的运行需要查看实际结果。决定性证据的核查仍是独立工作。
