# 决策引擎 3.0

本文件是单次决策内核，仍使用3.0记录协议。人生架构4.0在外层增加 [总控与九领域](人生总控架构.md)：全局目标、承诺和资源作为S1/S2输入，跨域合计进入S4，结果在S8回写个人快照。跨域整体可行性不能由某一个领域单独宣布。快照变化后主协调者更新受影响决定并重核，不能只保留原“通过”记录。

引擎由阶段、产物、检查条件与回退规则组成。23个模块是按需调用的知识、方法和工具，模块的名称或调用数量不代表决策完成。主协调者管理流程和取舍说明，R01审查证据与结论，用户保留价值选择和现实行为的决定权。

## 三类资源，贯穿八个阶段

| 主要职责 | 模块 | 使用方式 |
| --- | --- | --- |
| 领域与基础知识 | M02、M08—M12、M19—M21、M23的人文知识 | 给出领域事实、理论、约束和适用条件 |
| 决策方法 | M01、M03—M07、M13的调查实践方法、M14 | 对实际证据做推理、建模、比较和检验 |
| 信息处理与执行 | M15—M18、M22 | 取资料、处理数据、沟通、组织行动与反馈 |

这是主要职责分组，不是互斥学科分类。伦理与用户价值贯穿所有阶段；基础数学也可用于计算，经济知识也可产生可检验机制。英语检索、数据处理从S2就可使用，不能等到最终执行阶段才获取信息。

## 阶段、产物与回退

| 阶段 | 必须完成的工作 | 实际产物 | 不满足时怎么办 |
| --- | --- | --- | --- |
| S1 定义问题 | 区分学习知识、解释问题和实际选择；明确用户目标、期限、价值取舍、硬约束、可投入资源和允许行动 | 一句话决策问题；目标与约束及其来源 | 阻断性目标歧义只问关键问题；可先给有用条件分析，不猜预算和偏好 |
| S2 建立事实 | 分开用户陈述、外部事实、假设、估计、价值与未知；核验决定性来源和适用范围 | 带版本的输入快照、E证据账本、关键未知 | 返回具体来源或用户补证；列明获取成本、决定期限和暂缓代价 |
| S3 生成方案 | 从目标而非行业标签生成真实可选行动；考虑维持、暂缓或小规模试行；排除虚假陪衬 | 方案ID、行动内容、进入条件、资源需求、后果与退出方式 | 唯一方案需解释其他路径为何不可行；方案不现实则重新生成 |
| S4 约束与比较 | 先检查硬约束，再按不确定性选择比较方式；估计机会成本、最坏后果、他人回应和可逆性 | 逐方案约束检查、同口径比较、关键计算、反转条件 | 无可行方案则回S3或请用户修改S1约束；假设不足回S2，不能用评分抵消约束 |
| S5 反驳与复核 | 查决定性证据、关键计算、最强反对理由、竞争解释、遗漏选项与敏感点 | 本次版本的复核记录，问题及解决状态 | 按问题返回S1/S2/S3/S4，仅重做受影响部分；模型意见不按票数计证据 |
| S6 建议与取舍 | 按证据状态交付条件建议或可供选择的方案；区分事实不确定与用户偏好未定 | 建议、成立条件、具体缺口、用户选择及其来源 | 可以保留多个非支配方案，不强排唯一第一；用户未决定不编造决定 |
| S7 授权执行 | 根据会话已有授权核对具体动作范围、资源上限、验收、停止条件和复盘点 | 实际任务、真实执行状态、可观察预期 | 不把建议当授权；已有授权不重复询问。范围外动作停在草案，已授权的可逆工作继续 |
| S8 反馈更新 | 追加实际结果，区分判断、执行、外部条件和偶然性；检查什么假设被证据改变 | 原预测与新结果、差异解释、下一次调整 | 实质变化创建新输入版本，回到受影响的最早阶段，保留旧记录 |

简单可逆小事可把八阶段压缩成一段话，保留目标、约束、依据、取舍与下一步；纯排版和抄录无需启动引擎。紧急问题优先有根据的及时行动，不用完整记录耽误；注明尚未完成的检查。没有可并行的实质任务时单智能体执行；有独立子任务且值得拆分时按契约实际派工。

## S4 如何选择比较方法

- **只有明确硬约束：**先筛可行方案。某方案违反任一硬约束就不能被作为满足原条件的推荐；如果用户可能愿意放宽约束，把放宽后的问题作为另一个条件情景，不能静默修改。
- **有多个目标且偏好明确：**比较真实取舍、支配关系及用户认可的优先级。确有需要才评分；尺度、权重、重复计分与敏感性必须解释。未定偏好会改变排序时保留方案，不能把主观权重当事实。
- **有可信概率和收益后果数据：**可使用期望效用或决策树，同时检查不可承受损失、流动性和可逆性。期望值好不能覆盖用户的损失边界。
- **概率不可靠：**用明确标记的情景、区间、反转条件与稳健性比较，必要时比较最坏情景的损失或后悔；情景集合本身也不完备，不宣称“最优”。
- **结果受他人回应影响：**按已确认利益和信息列出合理回应，形成合作条件；不假设他人收益、人格或意图已知。
- **行动效果未知：**设计低成本、可逆且能区分重要假设的小试验。预先写指标、观察期、资源上限及停止条件，不能靠一次前后变化证明因果。

职业比较先把就业、创业与资产交易分开，再统一地区、时间、资历、职责、收入成本口径和样本取得方式。用户要求重新开始时，职业背景只用于真实约束，不能成为预设推荐方向。

## 三个独立状态

| 字段 | 允许值 | 含义 |
| --- | --- | --- |
| 建议状态 | 待补证／条件建议／建议可供选择 | 证据和分析支持到什么程度 |
| 用户选择 | 未知／未决定／已决定／暂缓 | 用户是否作出真实选择 |
| 执行状态 | 未知／未开始／执行中／已暂停／已完成／已停止 | 实际行动进行到哪里 |

用户已决定、已授权或已经成功一次，均不会自动提高建议状态。已选方案绑定当时目标、约束与具体内容；例如原先选择10元的方案，不能在同一ID变为1000元后沿用旧选择或授权。核对已有授权即可，不对范围未变的行动重复索要确认。旧2.0记录将“已决定”混在建议状态中，只按旧协议兼容读取；新记录使用3.0三字段，不改写旧历史。

“待补证”：存在使任何当前推荐都不成立的缺口，或尚无足够方案/比较/复核。“条件建议”：在可核验的条件下有具体可行建议，未知仍可能改变选择。“建议可供选择”：支持该建议的关键检查完成且无已知阻断性缺口，仍允许合理不确定性与用户取舍。

## 状态检查与版本

重要决策在人类可读记录旁建立一个结构化状态记录，使用 [引擎状态模板](../assets/模板/引擎状态.json)，字段与命令见 [状态记录规则](状态记录规则.md)。它引用证据、方案与产物，不复制整份资料。`scripts/decision_engine.py` 检查字段、引用、同版本复核、约束声明及建议状态是否一致，给出下一步。

该程序是对**已填记录**的规则检查，不会自动判断事实真伪、为未知条件打分、计算“人生成功率”，也不拦截当前客户端的所有工具动作。用户授权必须回到真实会话核对，JSON布尔值不能创造授权。

目标、关键事实、硬约束或方案发生实质变化时递增输入版本。比较和复核必须对应该版本；复核还绑定具体比较产物和建议对象，修改结论不能复用旧复核；旧版本结论作为历史保留，不用于宣称新版已完成复核。输入指纹还会检出未递增版本的内容变化；文字修正可仅重核受影响部分。程序无法证明作者是否真实重核，不能只复制新指纹宣称完成。

## 停止补证和停止循环

每次补证先写：补什么、哪些结果会改变选择、成本/时间上限、结果拿不到怎么办。无可靠概率时只做定性信息价值判断，不虚构精确价值。若不会改变可行方案或行动，停止重复研究；若预算用完、期限到达或来源不可得，报告剩余缺口与条件方案，不能无限复核或假装已通过。等待也是一个有成本的选项，不能默认“等证据完美”永远最好。

## 可核查的输出

展示建议状态、关键证据、方案取舍、最大未知、最强反对理由、反转条件、最小下一步与复盘触发。每个使用模块有实际输入、方法产物和局限；实际派工记真实任务ID与输入版本。只需要可核查的依据、公式与简明解释，不输出隐藏内部思维。
