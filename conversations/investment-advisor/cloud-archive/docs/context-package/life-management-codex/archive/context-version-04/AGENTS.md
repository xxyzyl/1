# Codex 工作规则

## 工作原则

1. 先读本包根目录文档和 `previous-artifacts/life-management/` 既有规则，再修改代码。
2. 先做最小可运行纵向切片，再扩展九领域、自动化和连接器。
3. 严格区分用户陈述、事实、估计、假设、未知、建议、用户选择和执行状态。
4. 重大目标、约束、方案或输入变化时创建版本；不得沿用旧结论而不重新核对。
5. 所有时间和费用按周期、单位和币种记录；共享事项只计一次，未知不能填零。
6. AI 负责理解、检索编排、解释和生成候选；资源核算、权限、状态迁移和关键校验使用确定性代码。
7. 用户对价值、底线、选择和外部授权拥有最终决定权。系统不得代替用户辞职、签约、交易、发信或公开发布。
8. 采用最小必要数据原则；敏感数据默认关闭，连接器必须可撤销、可纠正、可删除。
9. 每个重要建议都要显示依据、条件、代价、反转条件、观察窗口和最大未知。
10. 测试真实行为和边界，不用测试数量代替产品证据。

## 代码风格

- TypeScript 优先，严格类型，ESM 模块；Python 只用于明确的数据处理或检查脚本。
- 小模块、单一职责、显式输入输出；避免全局可变状态和隐式单例。
- API/数据库字段使用稳定英文 snake_case；用户界面默认简体中文。
- 时间统一存储 UTC ISO 8601，并保存用户时区；金额使用整数最小货币单位并保存 currency。
- 所有外部调用设置超时、重试上限、错误分类和审计记录；不把模型输出直接当作事实。
- 提交前运行格式化、类型检查、关键单元测试和构建；记录实际命令与结果。

## 禁止事项

- 禁止虚构用户、收入、留存、续费、市场规模、团队履历、连接器权限或实验结果。
- 禁止把钱学森理论或系统工程类比写成数学保证、医学建议或成功承诺。
- 禁止默认读取通讯、日历、文件、健康、金融或位置数据；必须有明确连接状态和用户可见范围。
- 禁止把九领域相加成单一“人生分数”，或让收入自动压过健康、关系、休闲和用户价值。
- 禁止未授权外发消息、交易、签约、辞职、发布或更改用户系统设置。
- 禁止把旧版本状态复制到新输入；禁止把“资源检查通过”写成事实正确或建议有效。
- 禁止为了展示而添加虚假图表、伪造产品截图、用户引言或增长曲线。

## 交付要求

每个功能附最小说明、验收条件、失败路径、数据权限说明和可回退方案。对外文案必须标明“已实现”“拟开发”“模拟场景”或“待验证”。
