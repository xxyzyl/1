# 日常使用指令

下面的文字可以直接对你自己的 Codex 说。它需要在当前项目中运行并具有所需的文件读写权限。每次先遵循 `AGENTS.md`。

## 记录一下

“请把我接下来提供的内容保存到 INBOX.md，保留原话并整理相关目标、行动和未知信息。直接完成已经授权的整理；只问会影响下一步的必要问题。不要把我的随口设想当成已确定目标。”

## 安排下一步

“请读取当前状态和行动记录，结合我实际可用的时间，建议最值得推进的一到三件事。说明每件事的完成标志、预计用时和对应目标。考虑阻碍、固定安排和休息，未确认的安排标注建议。”

## 帮我做一个决定

“请实际读取 METHODS.md、DECISION_PROTOCOL.md 和相关个人记录，按2.0协议处理这个决定。说明采用哪些方法、为什么适用、输入和产物是什么；需要补知识时查 RESOURCES.md 及相关原文。重要决定按 TEMPLATES/decision.md 保存，附关键证据、反对理由、敏感性、改变建议的条件与下一步。按 REVIEW_CHECKLIST.md 复核并实际运行结构检查，分别报告过程检查与证据缺口；不保证准确，不编造数字。”

## 检查这项能力是否学会

“请结合我正在学的内容和现实问题，设计一个能够完成的小任务，说明产物和检验标准。检查我的实际结果，再把证据和下一次练习写入 LEARNING.md。不要只根据我是否看完材料判断掌握程度。”

## 做一次周复盘

“请按 TEMPLATES/weekly.md 复盘最近七天（截至本次执行时，注明起止时间），先读取用户时区并确定日期范围；时区未设定时先澄清。只引用实际存在的相关记录，说明数据缺口。更新对应的复盘文件和索引，必要时更新当前摘要。提出下周一个最重要的调整，不擅自把建议变成我的承诺。”

## 恢复上下文

“请读取本项目规则、当前状态和相关源文件，用简短中文告诉我：目前在解决什么、已知限制是什么、最近做到了哪里、下一步是什么。把缺失或过期的信息单独说明。”

## 简化系统

“请检查最近的实际使用记录，指出哪些字段或流程没有帮助我做选择、推进事情或减轻负担。给出删减建议，先保留历史内容，再简化日常入口。”

## 检查一份建议是否符合规则

“请依据 DECISION_PROTOCOL.md 和 REVIEW_CHECKLIST.md 检查这份建议。列出实际采用的方法和产物，抽查关键事实与来源、复算影响结论的数字、找最强反对理由，并说明改变什么假设会改变结论。区分已执行和未执行的检查；不要用自我评价或结构检查通过替代真实性核验。保留原建议，并追加检查结果与必要修正。”

## 补充一个方法的资料与验证

“请根据 METHODS.md 的相关模块和 RESOURCES.md 找到该方法的可靠原始资料，实际阅读当前任务需要的部分，写明定义、适用条件、步骤、例子、反例或失效条件。用一个与当前任务不同的例子检查应用，再记录实际验证结果、来源和未掌握部分。请不要只增加书目，也不要把一次示例成功当作完全掌握。”
