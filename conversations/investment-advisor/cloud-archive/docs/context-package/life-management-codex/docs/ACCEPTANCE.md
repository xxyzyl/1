# ACCEPTANCE.md — 验收用例

## P0 必测场景

| 编号 | 场景 | 期望 |
|---|---|---|
| A01 | 用户创建职业转型目标，填写每周 10 小时可用时间 | 生成 life_snapshot 和 goal，未知项明确列出 |
| A02 | 同一周已有家庭承诺 2 小时，学习 4 小时，接单 5 小时，预留 1 小时 | 资源核算提示总需求 12 小时，超过 10 小时 |
| A03 | 一份作品同时用于学习和接单 | 共同行动只记一次，同时保留两个领域的收益说明 |
| A04 | 资源字段为 null | 返回未知，要求补证；不得按 0 计算 |
| A05 | 用户选择方案 A 后，可用时间从 10 小时变成 8 小时 | choice 历史保留，相关建议 validity_status 变成 stale |
| A06 | 用户撤销日历授权后，队列中等待写入日历的动作尚未执行 | outbox 停止该动作并写 audit_event |
| A07 | 重复提交同一 Idempotency-Key 的行动创建请求 | 不产生重复行动或重复外部动作 |
| A08 | 无模型 API key | mock provider 跑通 demo 和测试 |
| A09 | 模型返回没有来源的事实 | 拒绝进入 confirmed evidence，只能作为候选 |
| A10 | 用户纠正“每周 12 小时”为“每周 8 小时” | 创建新事实版本，依赖旧事实的建议进入复核队列 |
| A11 | 反馈尚未到观察窗口，例如学习三天后没有明显收益 | 不直接判定失败，提示等待或补充指标 |
| A12 | 两个用户的数据同时存在 | 任何查询、复核和行动只返回当前用户数据 |

## 产品试点指标

- 用户是否愿意真实填写目标、承诺和时间预算。
- 用户是否采纳系统提出的取舍调整。
- 每位用户每周需要多少人工支持。
- 用户是否愿意付费或续费。
- 系统维护成本是否低于它节省的决策和协调成本。
