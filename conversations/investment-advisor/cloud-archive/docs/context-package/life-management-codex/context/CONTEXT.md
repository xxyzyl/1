# CONTEXT.md — 项目上下文摘要

## 用户要做什么

用户希望把“人生管理系统”做成一个可以继续开发、可能商业化的 AI 产品。系统要借鉴系统工程、控制论和钱学森系统方法，把人生视为整体系统，由总控协调身体、心理、关系、职业、学习、财务、日常基础设施、社群责任和休闲体验九个领域，同时调用二十三个共享能力模块。

用户当前明确要求本包能交给本地 Codex，不看之前聊天记录也能继续开发。因此本包重写了根目录工程文档，并保存可运行方法源码、历史设计、流程图、PPT、上下文摘要和验证记录。

## 已形成的设计结论

- 人生价值、方向和底线由用户决定，放在系统最上层。
- 人生总控负责协调目标、承诺、资源、决策、执行和反馈。
- 单次重要选择沿用科学决策引擎 3.0 的八阶段流程。
- 人生系统 4.0 增加九个领域、共同资源账、主动服务协议和全局复核。
- 建议、用户选择和实际执行必须分开保存。
- 条件变化后旧建议需要复核，但历史选择不能被抹掉。
- 主动服务必须绑定数据源、目标、权限和通知频率，不能越权执行。

## 理论边界

关于钱学森系统方法，当前资料区分了《工程控制论》、系统工程和开放复杂巨系统综合集成方法。已保存的方法强调反馈、延迟、观测指标、系统边界、资源约束和实践检验。此前只核实了《工程控制论》的书目信息和相关介绍，不能宣称已完整通读原著。

## 商业化状态

商业化方向仍是假设。建议从在职职业转型用户切入，验证真实痛点、付费意愿、持续使用、人工服务成本和与通用 AI/日历/表格的差异。历史路演 PPT 是素材，不代表已经完成融资或真实市场验证。

## 本包没有包含什么

本包不是完整可运行 SaaS 产品；当前还没有真正的前后端应用、数据库迁移、登录、计费和外部连接器。本包也不是完整聊天记录导出，而是按项目继续开发需要整理的上下文。历史中曾提到的独立交互式脑图文件未在可访问资料中单独找到；本包保留了已找到的 HTML 预览、图片、PPT 和 JSON 图数据。
