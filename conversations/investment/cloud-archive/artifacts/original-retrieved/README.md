# 人生管理系统

## 1. 项目目标

人生管理系统是一套面向个人长期发展的“整体协调 + 科学决策 + 主动服务”系统。它把人生视为一个开放、复杂、持续变化的系统：用户负责确定价值、方向、底线和最终取舍；总控负责整合状态、目标、资源、承诺、行动与反馈；领域模块维护具体生活结果；共享能力模块提供知识、方法和工具。

系统不承诺替用户做出绝对正确的决定，也不把人生简化为单一分数。它的目标是减少信息遗漏、跨领域冲突、重复劳动和未经授权的行动，并帮助用户把重要决定转化为可执行、可复核、可更新的行动。

## 2. 产品定位

当前定位为：面向有职业转型、学习成长或复杂人生规划需求用户的个人决策与行动协调助手。

首个商业化验证场景建议聚焦“在职职业转型者的每周项目推进”，例如在有限时间内完成技能学习、作品、求职材料或副业试验。完整人生领域作为约束和影响背景按需参与，而不是首次使用时要求用户录入全部人生信息。

## 3. 核心设计

- 1 个总控：维护目标与底线、状态快照、跨域影响、共享资源、决策版本、执行授权和反馈。
- 9 个领域：D01 健康恢复；D02 心理状态；D03 关系家庭与照护；D04 职业劳动与价值创造；D05 学习能力与探索；D06 财务资产与保障；D07 居住日常与基础设施；D08 社群公共参与与生态责任；D09 休闲审美与生命体验。
- 23 个共享能力模块：逻辑、认识论、科学方法、调查研究、概率统计、基础数学、决策理论、运筹学、经济学、博弈与谈判、政治经济与制度、社会学、历史思想、心理学、健康、法律、财务、系统科学与控制、管理与项目、计算机与数据、AI与自动化、英语与原始资料、表达与人文审美。具体编号以 `docs/CONTEXT.md` 的可扩展清单为准，开发时应维护正式注册表。
- 8 个决策阶段：S1 定义问题；S2 建立事实与证据；S3 生成真实备选；S4 约束与比较；S5 反驳与复核；S6 建议与用户取舍；S7 授权执行；S8 反馈更新。
- R01 复核角色：检查证据、未知、反例、计算、遗漏、跨领域后果和版本是否过期。

## 4. 必须遵守的业务规则

1. 硬约束优先：预算、时间、法律、健康、照护和明确底线不能被综合评分抵消。
2. 三种状态分开记录：建议是否有依据、用户是否已选择、行动是否实际执行。
3. 没有执行记录时写“执行情况未知”，不能默认写成“尚未开始”。
4. 目标、证据、方案、资源或约束变化后，旧比较和旧复核必须重新核查。
5. 自动观察只能证明观察到的行为；计划不等于执行，执行不等于结果，结果不等于能力提升。
6. 资源跨领域只记一次；同一行动可以服务多个目标，但不能重复计算时间和费用。
7. 证据不足时使用区间、情景和反转条件，不伪造精确概率或分数。
8. 行动必须有单一主责、授权范围、验收标准、停止条件和效果观察窗口。
9. 默认最小化数据采集，用户可查看、修改、暂停同步、撤销授权和删除数据。

## 5. 当前进度

已完成：4.0 总体架构、9 领域划分、23 能力模块方向、3.0 八阶段决策协议、复核规则、共享资源核算思路、主动服务边界、理论应用边界、设计说明 PPT；已有方法包包含 23 个方法模块和 66 项来源记录，曾通过 6 个合成案例和 12 项结构检查，19 个决策回归测试及 13 个资源测试在此前工作中通过。

设计完成但尚未产品化：真实用户账户、持久化数据库、日历/任务/文件连接器、后台调度、通知、模型调用编排、权限系统、前端界面、计费、线上部署和长期效果评估。

重要边界：系统借鉴钱学森关于开放复杂巨系统的综合集成思想、系统工程的整体协调与验证确认、现代控制论对状态/观测/反馈/延迟的关注；不能据此宣称“人生可控”或“人生最优”。此前并未通读 1954 年《工程控制论》原著。
