# LEGACY_MIGRATION.md — 旧版资料迁移说明

## 资料来源

`archive/` 保留了此前多次打包或设计产出的资料。它们用于理解项目演进，不作为当前工程基线的最高优先级。

## 迁移规则

- 以根目录 `README.md`、`SPEC.md`、`ARCHITECTURE.md`、`TODO.md`、`AGENTS.md`、`.env.example` 为准。
- 旧版 v2 资料可迁移模板和概念，但不要直接沿用旧状态枚举。
- 旧版 SQLite、端口 8787、端口 3001 等设想仅作历史参考。
- 旧版个人档案中未知项较多，不要推断成真实用户信息。
- 旧 PPT 可提取概念和表达，但商业指标必须重新核实。

## 状态迁移

旧文档里如果只有“建议/决定/执行”混合状态，迁移时拆成三列：recommendation_status、choice_status、execution_status。无法判断的字段填 `unknown`，不要根据上下文猜测。

## 用户数据迁移

只迁移用户明确确认过的目标、承诺、偏好和事实。历史聊天摘要可作为背景，但不能当作完整、准确、永久有效的用户数据库。
