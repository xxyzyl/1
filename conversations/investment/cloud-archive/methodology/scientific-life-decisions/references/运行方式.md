# 运行方式与能力边界

## 当前 ChatGPT Work

在技能选择器选择“科学决策与人生管理”，或在可识别技能的输入中使用其名称。Codex CLI/IDE 可用 `$scientific-life-decisions`。是否自动匹配取决于当前客户端和技能目录；重大问题显式调用更容易核对加载情况。

本Skill的主协调者承担人生总控，使用当前已暴露的协作工具按需启动角色，再收集真实结果。23张M能力卡、9张D人生领域卡和1张R01复核卡共33个可选角色，不是33个常驻进程；没有协作工具时顺序执行并如实说明。

## 主动服务的实际启用

按 [主动服务协议](主动服务协议.md) 执行。当前会话可直接开展主动补问、读取已有授权资料及提出建议；跨会话持续工作另需实际的数据连接、持久个人记录、触发任务和通知渠道。模板见`assets/模板/主动服务设置.md`，填写后仍须实际验证。

先检查是否已有覆盖相同目标的任务，优先更新而非重复创建。调度提示词应明确调用本Skill、真实状态库位置、关注目标、授权来源、触发或周期、去重和结果记录要求。依次验证实际读取、状态写入、一次完整分析和通知送达；任一环节不可用则报告具体已完成/待接入项，不能称全自动已上线。

候选频率与真实任务分开；本Skill不会自动生成定时器。具体产品是否支持事件触发、后台读取本地文件、条件静默等，按部署时的官方说明和可用工具验证，不把设计能力当成平台现成功能。

## 生成派工消息

在当前允许的工作目录准备 JSON 任务文件。不要把真实个人任务保存进 Skill。下面是合成示例：

```json
{
  "task_id": "sample-001",
  "decision_id": "sample-decision-001",
  "phase": "S4",
  "revision": 1,
  "question": "六小时内怎样安排两项学习任务并保留缓冲？",
  "goals_constraints": "每周最多六小时；练习A至少两小时，练习B至少一小时；其余偏好未知。",
  "facts_evidence": "E01：合成场景给定时间与下限，不是用户真实情况。",
  "unknowns": "任务实际耗时波动、优先级尚未知；请给条件方案。",
  "deliverable": "可行分配、时间合计、关键假设和调整条件。",
  "allowed_actions": "只研究和计算，返回结果，不修改共享文件。"
}
```

运行 `python3 <技能目录>/scripts/dispatch.py task --module M06 --brief <任务文件绝对路径>`。3.0派工必须有decision_id、phase和revision，重要决策还应传入input_fingerprint。输出包括 `task_name`、完整 `message` 和 `dispatch_status: not_dispatched`。主协调者随后调用实际工具；脚本没有网络请求、模型调用或后台任务。

`list` 子命令列出全部角色。任务输入模板只是传递结构，不决定科学正确性；生成消息不等于完成研究。

D01—D09任务还必须包含非空`global_snapshot_id`与正整数`global_revision`。`goals_constraints`包含共同资源约束；`facts_evidence`包含相关快照事实及实际出处。生成器会嵌入统一契约、领域协议和对应卡片。只分派有独立价值的工作，总控本身由当前主协调者承担。

## 电脑端 Codex 的角色配置

官方文档支持个人 `~/.codex/agents/` 或项目 `.codex/agents/` 下的独立 TOML 文件，每份定义 name、description、developer_instructions。本 Skill 提供生成器，完整嵌入契约和模块方法，不依赖固定的安装路径，也不修改模型、审批、沙箱或全局配置。

只有用户要求配置那台机器或该项目且实际具有访问能力时，执行：

```bash
python3 <技能目录>/scripts/dispatch.py export-agents --target <目标项目的绝对路径>/.codex/agents
```

会生成23个能力角色、9个人生领域角色和1个复核角色。已有相同内容会跳过，已有不同内容则拒绝覆盖。不得将导出成功说成客户端已识别或代理已运行；需在目标Codex客户端实际验证调用。当前Work不需要这一步，也不能用云端文件假称用户电脑已经配置。

## 人生架构4.0的共同资源核算

先读 [总控架构](人生总控架构.md)，在个人资料空间复制`assets/模板/人生资源账.json`；不把真实账本放进通用Skill。每个账本只覆盖一个明确周期，按资源分别声明容量、基线、保留量及各行动需求；未知用null，无需用0。

运行`python3 <技能目录>/scripts/check_life_resources.py <账本绝对路径>`。各组合分别给出“资源可行/资源冲突/待补资源数据”。退出0表示输入有效且核算完成，包括发现冲突的情况；退出2表示输入无效。输出指纹关联本次输入，不是审批或真实状态证明。

已有承诺使用`committed`，候选行动使用`proposed`。一个情景须包含所有账本内已有承诺；同一行动ID仅出现一次，关联多个领域不重复求和。真实承诺已更改时先更新来源与全局版本，再改账本；不能为让核算通过而静默删去承诺。模板只是待填结构，不是实际个人计划。
