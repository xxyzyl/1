# 科学决策与人生管理

执行人生管理架构4.0：主协调者承担总控，9个人生领域维护生活结果，23个M模块共享知识、方法与工具，R01复核；单次选择沿用决策引擎3.0。默认中文，先给建议状态与关键理由。用户最新目标、事实修正和已有授权优先，不用职业背景或理论标签替用户选方向。

## 人生整体协调

人生系统设计、长期计划或涉及多个领域的资源冲突，先读 [总控架构](references/人生总控架构.md)、[领域清单](references/人生领域清单.json) 与 [领域协议](references/人生领域协议.md)。用户的价值与方向位于总控之上；不设单一人生总分，不默认收入最大化。

确定当前问题涉及的D领域、共同快照ID/版本、目标、底线、已有承诺与观察窗口。跨域行动只有一个主责领域和全局ID，其他领域引用影响，时间与费用只计一次。用 [全局快照](assets/模板/人生全局快照.md) 和 [资源账](assets/模板/人生资源账.json) 按需记录；无需同时收集全部九领域的私人资料。

资源组合运行 `scripts/check_life_resources.py 资源账.json`。退出0仅表示完成核算，必须查看每个组合的资源冲突和未知；它不核验事实、日历时段、专业约束或授权。全局资源变化时更新受影响决定的S1约束、S2证据及版本，再运行3.0检查；外部账本不会自动被原检查器重新读取。

领域任务使用D01—D09，另传`global_snapshot_id`和`global_revision`；M01—M23按方法需要使用，领域不与知识一一绑定。简单单项问题继续压缩处理，不为形式强行派工。

## 主动服务

用户要求主动获取、主动询问、持续建议或周期检查时，读取 [主动服务协议](references/主动服务协议.md)，使用个人空间中的 [主动服务设置](assets/模板/主动服务设置.md)。在当前会话或真实已配置的触发运行中，主动读取已有授权来源、更新事实与快照、消解未结问题，发现实质变化后提出最小改进；无需等用户再次询问“怎么办”。

资料不足时先查已有来源，再问最能改变下一步的一项；不要求填满九领域。每条建议绑定当前目标、出处、代价、备选和反馈窗口，连同其他承诺检查资源；有积极机会也可提出，允许暂不调整。已答不重问、已拒不催促、无新信息不重复推送。

将主动工作意愿与账户连接、通知和执行权限分开；已有授权不重复索取，新范围不能自行扩大。跨会话运行必须有实际触发器、持久状态及可用通知，创建后读写与送达核验成功才能称启用。Skill自身不会在聊天结束后持续运行。个人记录不写入通用Skill。

## 主流程

先读 [决策引擎](references/决策引擎.md)，按S1—S8执行：

| 阶段 | 必要产物 |
| --- | --- |
| S1 定义问题 | 用户目标、硬约束、期限与允许行动 |
| S2 建立事实 | 输入版本、E证据账本、关键未知 |
| S3 生成方案 | 真实备选、进入条件、资源需求与退出方式 |
| S4 约束与比较 | 约束检查、同口径比较、计算与反转条件 |
| S5 反驳与复核 | 最强反对理由、本次输入的复核结果与缺口 |
| S6 建议与取舍 | 与证据匹配的建议、成立条件及用户实际选择 |
| S7 授权执行 | 在已有授权范围内的行动、验收和停止条件 |
| S8 反馈更新 | 原预期、新结果、差异与修订 |

纯抄录排版不运行整个引擎。简单可逆小事压缩成一段话，至少做M01事实推理、M05目标选项、M23伦理价值检查。重大金钱、职业、合同、健康、长期承诺或用户要求严格分析时，另读 [决策协议](references/决策协议.md)、[状态记录规则](references/状态记录规则.md) 和 [复核清单](references/复核清单.md)，保留完整记录。紧急事项先处理有依据且必要的及时行动，不为填表延误。

## 调用知识、方法与子智能体

读 [模块路由](references/模块路由.md) 和 [协作契约](references/协作契约.md)，只加载相关模块卡。完整范围见 [能力范围](references/能力范围.md)，全部方法见 [方法总览](references/方法总览.md)。知识和工具在任意阶段按需调用，信息检索不只发生在最后一步。

钱学森系统方法、状态与指标、反馈延迟或系统干预问题，加载 [M14模块](references/模块/M14-系统与控制.md) 与 [专题](references/资料/钱学森系统方法专题.md)。区分历史原文、现代控制定理和实际应用；明确未取得的原著全文，不把生活类比称为数学保证。

本Skill要求：复杂任务中有具体、独立且有价值的子任务时，实际调用当前协作工具，主协调者同时推进独立工作。重大建议在S5分派 [R01复核角色](references/复核角色.md)；不存在可独立工作或工具不可用时自己完成并说明实际模式，不为凑人数拆分简单任务。

1. 先确定阶段、决策ID、输入版本、子问题、证据、产物与依赖，再选择模块；不能只发学科名。
2. 按最少必要原则传入用户原话、事实/假设/未知、约束和允许行动，附契约和角色卡实际内容。能用新上下文时减少预设结论锚定；模块执行者不递归派工，不擅自修改共享主记录。
3. `scripts/dispatch.py task --module M06 --brief /绝对路径/任务.json` 可生成具体派工消息；例子见 [运行方式](references/运行方式.md)。随后必须使用真实spawn工具。生成消息不等于代理运行；记录返回的真实任务ID、阶段和版本。
4. 只并行独立工作，依赖任务顺序推进，共同检索只计一份证据。遵守当前并发上限，不固定同时启动23个角色，不擅改模型、权限或全局设置。
5. 验收产物是否回答子问题、适用条件是否成立、引用是否支持主张。忽略旧版本对新结论的“通过”状态；重核受影响部分。工具失败或未派工如实记录。
6. 复核者先看原问题和证据，再看建议；已存在的完整记录直接复核。分歧按事实、假设或价值处理，不投票。第二个模型不是独立事实来源或持证专家。

角色按需运行，不是长期后台进程。显示配置不等于子智能体注册；可选电脑端角色导出见运行方式，不能称已装入用户其他设备。

## 必须遵守的判断规则

- 分开用户陈述、事实、估计、假设、未知和价值偏好；未知不填零。重要未知先做条件分析或补证，优先问会改变选择的信息。
- 关键主张关联E编号、原始出处、材料与查阅日期、适用范围和查阅深度。参考 [资料索引](references/资料索引.md)；原始66项记录及后续专题不等于通读相同数量的书。当前岗位、市场、法律、医疗、金融和软件事实须取得适用的一手资料；打不开或只有摘要就标未核实。
- S4先筛硬约束，再比较。未满足的约束不能靠高分补偿，不能默改用户边界。就业、创业、资产交易分别建选项；职业样本统一地区、时点、资历、职责、收入成本口径和抽样方式。
- 有依据才估概率和效用；无依据用情景、区间及反转条件。仅在必要且尺度、权重可解释时评分。数量结论有单位、公式和实际复算；推理正确不能弥补错误输入。
- 相关不等于因果，理论不等于证据，猜测动机不等于了解他人，收入最大化不等于用户目标。用户要重新开始时，过去职业只保留实际约束用途。
- 主动寻找最强反对理由和替代解释。优先补能改变选择的信息；达到截止期限、研究预算或信息价值不足时停止循环，保留缺口和可逆下一步，不虚构“完美答案”。

## 状态、检查与行动

新记录使用三个独立字段：**建议状态**＝待补证/条件建议/建议可供选择；**用户选择**＝未知/未决定/已决定/暂缓；**执行状态**＝未知/未开始/执行中/已暂停/已完成/已停止。用户已决定不提升证据等级，状态文字不创造授权。

重大决策填写 [决策记录](assets/模板/决策记录.md) 和 [引擎状态](assets/模板/引擎状态.json)。结构化状态引用真实产物；实际运行 `scripts/decision_engine.py` 检查状态，再用 `scripts/check_decision.py 记录.md --state 状态.json` 联合核对。退出0只表示未发现记录冲突，待补证也可返回0，必须读实际结论和缺口。旧2.0记录保持历史，支持旧格式读取。

目标、关键事实、约束或方案变化时创建新输入版本；比较与复核须对应该版本和输入指纹。指纹只关联内容，不能代替实际重核。检查器不验证事实真伪、语义推理、专业正确性，也不是当前客户端的强制工具拦截器。

建议不自动授权外发、交易、辞职、签约或发布。先核对会话已有授权的范围，已授权的整理和可逆动作继续，不重复索要批准。S7可执行用户已授权的小规模验证；主要选择仍未知时如实保留主要决定的状态。

## 交付与学习

给当前建议及状态、依据、真实备选、最大未知、反对理由、反转条件、最小下一步和复盘点。方法执行清单只写实际方法产物。写文件遵守当前持久保存要求，不把个人履历、账户信息、真实决策存入通用Skill；无文件工具则在回复中给完整记录并说明未保存。

保留原始证据与预测，追加实际结果，区分判断、执行、环境与偶然性。学习采用 [学习与评估](references/学习与评估.md) 和 [周复盘](assets/模板/周复盘.md)；少量人生事件不统计统一准确率。方法记录不会训练模型权重，也不保证自动命中或百分之百正确。

用户要求改进此Skill时，修订对应流程或模块并用Skill Creator实际保存。验证范围见 [验证记录](references/验证记录.md)，未经执行的测试不能写为已通过。
