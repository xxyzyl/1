# 人生管理系统｜本地 Codex 工程上下文包

整理日期：2026-09-07。移交包版本：1.0。整体架构：4.0；单次决策协议：3.0。**本包包含工程规范、现行方法源码、可运行检查工具和历史产物；尚不包含完成的 Web 产品。**

## 项目目标与产品定位

帮助用户把目标、现实条件、备选方案、行动和结果连起来，在工作、学习、家庭、健康、财务等领域之间持续协调。用户决定什么值得追求；系统整理事实、暴露冲突、比较取舍、在已有授权内协助执行，并根据实际结果更新判断。

长期产品定位是主动的个人决策与行动协调助手。它应尽量减少用户录入：读取已经授权的数据，资料不足时主动问最能改变下一步的一项，证据足够时提出具体改进，没有实质变化时保持安静。系统需要同时解释“为何这样建议”“占用什么资源”“何时需要改变”。

首个验证场景沿用历史提议：在职转型者协调学习、作品、求职或小规模接单，同时保留原有生活承诺。**这是待验证的切入点，不是用户已经批准的唯一市场。**先支持一个真实目标和相关两三个领域，再按需要扩展；不要求先填满整个人生档案。

## 核心结构与功能

| 组成 | 职责 |
| --- | --- |
| 用户价值与方向 | 目标、底线、已有承诺、偏好和实际选择 |
| 人生总控 | 共同快照、跨领域影响、资源组合、版本失效、执行与反馈协调 |
| D01—D09 | 身体、心理、关系、职业、学习、财务、日常基础设施、公共参与、休闲体验 |
| M01—M23 | 按问题调用知识、推理、统计、调查、系统分析、数据和执行方法 |
| S1—S8 | 定义问题→建立事实→生成方案→约束比较→反驳复核→建议取舍→授权执行→反馈更新 |
| R01 | 审查本次版本的证据、计算、反例、资源及遗漏；不是独立事实来源 |
| 主动服务基础设施 | 数据接入、持久状态、真实触发器、问题与建议去重、通知及失败恢复 |

九领域和二十三模块是可演进的分类，不代表必须运行三十二个进程。主总控按需调用；导出角色共33份（9个D、23个M、1个R），总控本身由主协调者承担。

必须保留的规则：未知不填零；计划不等于发生；建议、用户选择、执行分开；先筛硬约束；同一行动跨领域只记一次资源；目标、事实或预算变化后重核受影响决定；频繁采集不意味着频繁改策略；不生成统一人生总分。

## 本地怎么接手

解压后打开 `life-management-codex` 目录。先看 [START_HERE.md](START_HERE.md)，把其中的开发指令交给本地 Codex。此包不会安装或修改你电脑上的 Codex，也没有替你启用账户、后台任务或外部操作。

已有 Python 3.12 环境时，在该目录可直接复验，无需模型密钥或第三方包：

```bash
python3 -m unittest discover -s methodology/scientific-life-decisions/scripts -p 'test_*.py' -v
python3 methodology/scientific-life-decisions/scripts/system_control_examples.py --self-test
python3 methodology/scientific-life-decisions/scripts/check_life_resources.py examples/resources-over-budget.json
```

最后一条应报告资源冲突，并正常退出0；退出0表示完成核算，不表示方案可行。Windows 可在上述命令中将 `python3` 换成实际已安装的 Python 3.12 解释器。
