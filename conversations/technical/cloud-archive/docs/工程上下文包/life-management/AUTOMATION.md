# 自动化：在日常流程稳定后加入

本文件是配置指南，没有创建任何定时任务或后台进程。

先手动运行一次 `WORKFLOWS.md` 的周复盘，确认输出有用、文件保存位置正确，再决定是否自动运行。

## 已有提醒

本次聊天已经创建“每周复盘学习成果”，时间为每周日北京时间 20:00 左右。它会提醒并引导复盘，不会自动读取你电脑上这套项目文件。此处只是交付时的说明，不能代替将来查询任务真实状态。

## 使用支持本地项目的桌面客户端

官方文档说明，桌面端定时任务可以访问本地项目；依赖本地文件时，电脑需要开机、应用保持运行，项目也要仍在原位置。具体入口和功能可用性以你的版本和账号为准。

如果需要自动生成本地周报，可以在该客户端中明确要求把任务关联到这个项目，指定时间和时区，并使用以下执行提示词：

> 在 life-management 项目中读取 AGENTS.md、NOW.md、PROFILE.md 和相关索引。按照 TEMPLATES/weekly.md 复盘用户时区下最近七天（截至本次执行时，注明起止时间）。只使用实际存在且属于该周期的记录；缺少数据时写明局限，不补造进展。写入 REVIEWS 中对应周期的文件并更新索引，只更新有证据变化的当前摘要。同一周期已有复盘时追加修订说明。建议保持为建议，不自动新增承诺或外部行动。最后报告保存位置和最重要的一个发现。

配置前将用户时区、实际目录和执行时间填写明确。检查同类任务是否已经存在；如果决定用本地周报替代已有提醒，再按用户要求修改或停用旧任务。先查看首次实际运行结果，再依赖后续自动执行。

## 使用 Codex CLI 或 VS Code 扩展

它们可用于手动执行和验证这个工作流程，官方文档说明二者没有 Scheduled 管理界面。第一版继续使用已有提醒，到时间打开本地项目并要求复盘即可。

如果以后需要操作系统级定时执行，应另行结合你的系统、Codex 认证、文件权限、失败日志和通知方式设计。这个起步包没有安装 cron、systemd 或其他后台任务。

## 使用网页或手机

网页任务可以使用上传的材料和已连接的工具，但不能直接访问电脑本地目录。可以提供必要的周记录摘要，或者在用户明确要求后配置适合的同步方式。不要把“同一账号”当成所有本地文件已经同步。
