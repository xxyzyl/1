# 开发任务

## P0：先做可运行、可审计的核心闭环

- [ ] 创建项目骨架、依赖锁定、测试和本地启动说明。
- [ ] 定义领域实体 schema、枚举、状态机和版本字段。
- [ ] 实现目标、约束、承诺、证据、决策、行动、观察的 CRUD。
- [ ] 实现 S1-S8 最小状态机和回退规则。
- [ ] 实现建议/选择/执行三状态分离；无执行记录显示“执行情况未知”。
- [ ] 实现硬约束检查、时间/预算单位校验和共享资源去重。
- [ ] 实现证据/目标/方案/资源变化后的 stale 检查。
- [ ] 实现 R01 复核清单和结构化复核结果。
- [ ] 实现审计日志、导出、删除和数据恢复基础能力。
- [ ] 编写回归测试：至少覆盖 AGENTS.md 中列出的边界案例。

## P1：做出可连续使用的本地原型

- [ ] 做简洁首页：当前目标、下一行动、变化、用户取舍。
- [ ] 支持自然语言输入并转成候选结构，必须经过用户确认才能成为事实。
- [ ] 支持文件导入和来源追踪。
- [ ] 支持每周复盘、延迟效果窗口和“未观察到”状态。
- [ ] 接入一个日历或任务来源，默认只读、可暂停、可撤销。
- [ ] 增加提醒去重、安静时段和提醒上限。
- [ ] 增加成本、耗时、错误和人工辅助工时统计。

## P2：小规模验证与产品化

- [ ] 以职业转型场景邀请 5—10 名自愿用户试用四周。
- [ ] 记录目标进展、维护负担、错误、人工工时、直接成本、继续使用和真实付费意愿。
- [ ] 比较系统使用前后的基线，避免把人工陪伴效果误算为软件能力。
- [ ] 根据验证结果决定做深某一功能，还是扩展到独立网站/App。
- [ ] 增加多租户、权限、加密、密钥管理、隐私设置和合规评估。
- [ ] 增加模型网关、费用预算、提示版本和输出评估。

## P3：后续连接与商业能力

- [ ] 日历、任务、文件、邮件和消息连接器。
- [ ] 后台调度和可靠重试。
- [ ] 订阅或按项目收费试验。
- [ ] 团队/顾问协作和人工复核工作台。
- [ ] 移动端与跨设备同步。
